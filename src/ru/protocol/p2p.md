# Сетевой протокол Minecraft на базе WebRTC

Эта статья описывает архитектуру и реализацию сетевого стека XMCL, позволяющую играть по сети между пользователями из разных локальных сетей с помощью технологии WebRTC без необходимости использования стороннего ПО для VPN (Hamachi, Radmin) и без ручной настройки проброса портов (port-forwarding) на роутере.

---

## Что такое WebRTC? Почему именно он?

WebRTC (Web Real-Time Communication) — это открытый стандарт и стек протоколов для прямого однорангового (peer-to-peer) взаимодействия в реальном времени.

Официальное определение:
> WebRTC (Web Real-Time Communications) — это технология с открытым исходным кодом, обеспечивающая передачу данных между браузерами и приложениями по схеме point-to-point с минимальными задержками.

Хотя WebRTC изначально проектировался для аудио- и видеопотоков в вебе, его модульная архитектура и наличие надежных бинарных каналов данных (`RTCDataChannel` на базе SCTP/DTLS) идеально подходят для игровых лаунчеров.

### Сравнение методов сетевой игры

| Характеристика | WebRTC (XMCL) | Собственный Hole Punching | Сторонние VPN (Hamachi, Radmin) |
| :--- | :--- | :--- | :--- |
| **Кастомизация** | **Высокая** | **Максимальная** | Отсутствует |
| **Сложность разработки** | **Умеренная** | **Критически высокая** | Минимальная |
| **Удобство для игрока** | **В 1 клик (Zero-Config)** | Зависит от клиента | Требует установки драйверов и прав админа |
| **Безопасность** | **Сквозное DTLS-шифрование** | Зависит от протокола | Зависит от провайдера VPN |
| **Задержка (Latency)** | **Минимальная (P2P direct)** | Минимальная | Повышенная из-за серверов-посредников |

## Детали протокола и архитектура

Сетевой протокол XMCL состоит из трех основных уровней:

1. **Сигнализация и согласование (Signaling & ICE)**: Обмен параметрами сессий (SDP Offer/Answer) и кандидатами ICE через сигнальный сервер для обхода NAT и фаерволов.
2. **Канал метаданных (Metadata & Control Channel)**: Управляющий канал `metadata` для передачи информации о комнате, списка игроков, пинга и манифестов модов.
3. **Туннелирование трафика Minecraft (Game Tunneling)**: Проксирование бинарного TCP-трафика игры через надежный канал данных WebRTC (`ordered: true`).

### Основные концепции

* **Хост (Host)**: Игрок, запускающий мир Minecraft и открывающий его для локальной сети (`Open to LAN`). Лаунчер хоста создает комнату и ожидает подключения.
* **Гость (Guest)**: Игрок, подключающийся к комнате хоста через P2P-сеть. Лаунчер гостя эмулирует появление LAN-сервера в меню мультиплеера Minecraft.
* **Сервер сигнализации (Signaling Server)**: Легковесный сервер-посредник, используемый исключительно для первоначального обмена SDP-пакетами. Игровой трафик через него **не проходит**.
* **STUN / TURN серверы**:
  * **STUN**: Позволяет узлам узнать свой внешний публичный IP-адрес и тип NAT.
  * **TURN**: Резервный ретранслятор, используемый только при симметричном жестком NAT, когда прямое P2P-соединение физически невозможно.

## Жизненный цикл сессии и передача данных

```
Host (Minecraft Server)          XMCL Host                Signaling / STUN              XMCL Guest             Guest (Minecraft Client)
       |                            |                            |                          |                             |
       |  1. Open to LAN (Port X)   |                            |                          |                             |
       |--------------------------->|                            |                          |                             |
       |                            |  2. Create Room (SDP Offer)|                          |                             |
       |                            |--------------------------->|                          |                             |
       |                            |                            |  3. Join & Get Offer     |                             |
       |                            |                            |<-------------------------|                             |
       |                            |                            |  4. Send SDP Answer      |                             |
       |                            |  5. Receive SDP Answer     |<-------------------------|                             |
       |                            |<---------------------------|                          |                             |
       |                            |                            |                          |                             |
       |                            |<<<<<<<< Direct P2P ICE Hole Punching >>>>>>>>>>>>>>>>>|                             |
       |                            |                                                       |                             |
       |                            |  6. Metadata: LAN Discovery Packet (MOTD, Port X)     |                             |
       |                            |======================================================>|                             |
       |                            |                                                       |  7. UDP Fake LAN Broadcast  |
       |                            |                                                       |---------------------------->|
       |                            |                                                       |                             |
       |                            |                                                       |  8. Connect to Local Proxy  |
       |                            |                                                       |<----------------------------|
       |                            |  9. WebRTC DataChannel (Raw Minecraft TCP Tunnel)     |                             |
       |<===========================|<======================================================|<----------------------------|
```

### Этап 1: Сигнализация и рукопожатие ICE

1. Хост создает объект `RTCPeerConnection` и формирует `SDP Offer`.
2. Оффер передается на сервер сигнализации комнаты.
3. Гость получает оффер хоста, применяет его как `RemoteDescription`, формирует `SDP Answer` и возвращает хосту.
4. Стороны обмениваются кандидатами ICE (`RTCIceCandidate`) через STUN. После нахождения рабочего сетевого маршрута устанавливается прямое P2P-соединение.

### Этап 2: Обнаружение локального мира (LAN Discovery)

Когда хост в одиночной игре нажимает **«Открыть для сети»** (`Open to LAN`), Minecraft начинает отправлять UDP-сообщения на мультикаст-адрес `224.0.2.7:4445`:

```text
[MOTD]World Description[/MOTD][AD]54321[/AD]
```

Лаунчер XMCL перехватывает это сообщение, извлекает порт (`54321`) и текст MOTD, после чего отправляет JSON-пакет в канал управления `metadata` гостя:

```json
{
  "type": "lan-discovery",
  "motd": "Vova's World",
  "port": 54321
}
```

Лаунчер гостя получает этот пакет, запускает локальный TCP-прокси и отправляет локальный UDP-мультикаст на ПК гостя. В результате у гостя в меню **Сетевая игра** автоматически появляется мир хоста, как если бы они находились в одной комнате.

## Архитектура туннелирования игрового TCP-трафика

Minecraft использует стандартный протокол поверх TCP. Поскольку WebRTC оперирует UDP, для передачи игрового потока XMCL создает надежный двунаправленный канал данных:

### 1. Инициатор туннеля (Клиент гостя)

```typescript
import net from 'net';

function setupGuestTunnel(peerConnection: RTCPeerConnection, remotePort: number, motd: string) {
    // Создаем локальный TCP-прокси на стороне гостя
    const proxyServer = net.createServer((tcpSocket) => {
        // Создаем надежный упорядоченный бинарный DataChannel для сетевого сокета
        const gameChannel = peerConnection.createDataChannel(remotePort.toString(), {
            protocol: 'minecraft',
            ordered: true
        });

        // Передаем данные TCP из Minecraft в DataChannel WebRTC
        tcpSocket.on('data', (data) => {
            gameChannel.send(data);
        });

        // Передаем бинарные данные WebRTC обратно в локальный TCP сокет
        gameChannel.onmessage = (event) => {
            tcpSocket.write(Buffer.from(event.data));
        };

        tcpSocket.on('close', () => gameChannel.close());
        gameChannel.onclose = () => tcpSocket.destroy();
    });

    // Слушаем случайный свободный локальный порт
    proxyServer.listen(0, () => {
        const localPort = (proxyServer.address() as net.AddressInfo).port;
        // Транслируем локальный порт, чтобы меню мультиплеера Minecraft его увидело
        broadcastLocalLanDiscovery(motd, localPort);
    });
}
```

### 2. Приемник туннеля (Сервер хоста)

На стороне хоста лаунчер слушает событие `ondatachannel`. При появлении нового канала с протоколом `minecraft` он открывает локальное TCP-соединение к реальному серверу Minecraft:

```typescript
import net from 'net';

function setupHostTunnelReceiver(peerConnection: RTCPeerConnection) {
    peerConnection.ondatachannel = (event) => {
        const gameChannel = event.channel;
        if (gameChannel.protocol !== 'minecraft') return;

        const targetPort = parseInt(gameChannel.label, 10);
        // Подключаемся к реальному запущенному миру Minecraft на ПК хоста
        const minecraftSocket = net.connect(targetPort, '127.0.0.1');

        gameChannel.onmessage = (e) => {
            minecraftSocket.write(Buffer.from(e.data));
        };

        minecraftSocket.on('data', (data) => {
            gameChannel.send(data);
        });

        gameChannel.onclose = () => minecraftSocket.destroy();
        minecraftSocket.on('close', () => gameChannel.close());
    };
}
```

## Формат сообщений канала метаданных

Канал `metadata` передает управляющие события в формате сериализованного JSON:

### Спецификация сообщений

| Тип (`type`) | Направление | Описание |
| :--- | :--- | :--- |
| `identity` | Двустороннее | Передача никнейма, UUID игрока и текстуры скина |
| `lan-discovery` | Хост -> Гость | Информация о LAN-мире (порт, MOTD, режим игры) |
| `chat` | Двустороннее | Текстовые сообщения встроенного P2P-чата |
| `manifest-sync` | Хост -> Гость | Список модов хоста для валидации совместимости |
| `heartbeat` | Двустороннее | Проверка активности соединения и замер P2P-пинга |

### Пример пакета синхронизации модов

```json
{
  "type": "manifest-sync",
  "minecraft": "1.20.1",
  "modloader": "fabric-0.15.11",
  "mods": [
    { "id": "sodium", "version": "0.5.8" },
    { "id": "iris", "version": "1.7.0" }
  ]
}
```

## Безопасность и изоляция

1. **Шифрование данных**: Все соединения WebRTC обязаны использовать протокол **DTLS** (Datagram Transport Layer Security). Трафик между игроками полностью зашифрован и защищен от перехвата провайдером.
2. **Защита локальной сети**: Лаунчер проксирует только сетевой трафик, связанный с указанным портом инстанса Minecraft. Гость не получает доступа к файловой системе хоста или другим сервисам локальной сети.
3. **Безопасность ключей**: Подключение к комнате требует одноразового ключа или приглашения в сессию, предотвращая несанкционированное сканирование портов.
