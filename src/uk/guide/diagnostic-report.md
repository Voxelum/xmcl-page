# Діагностичний звіт (.zip) та приватність

::: tip ЦЕНТР ДІАГНОСТИКИ ТА ЗБОЇВ
Шукаєте способи вирішення проблем із запуском чи коди виходу?
- **[Вирішення проблем із запуском та збоями](./troubleshooting.md)** - помилки середовища Java, розподіл пам'яті, драйвери та конфлікти модів.
- **[Журнали збоїв та коди виходу](./crash-logs.md)** - шляхи до журналів (`latest.log`, `crash-reports`), коди 0xC0000005, 1, 137 і читання стектрейсу.
:::

Під час діагностики складних проблем із лаунчером, помилок peer-to-peer з'єднання або збоїв завантаження бібліотек розробники чи помічники спільноти можуть попросити вас надати **Діагностичний звіт XMCL** (Diagnostic Report).

Цей посібник розповідає, як створити такий звіт, які технічні дані він збирає, і як XMCL гарантує захист ваших особистих даних і безпеку акаунтів.

---

## 1. Як створити діагностичний звіт

Експортувати звіт можна безпосередньо з інтерфейсу XMCL:

1. Відкрийте **Налаштування** (іконка шестерні на бічній панелі ліворуч).
2. Перейдіть до розділу **Сховище** або **Діагностика**.
3. Натисніть кнопку **Експортувати діагностичний звіт** (або комбінацію `Ctrl+Shift+D` / `Cmd+Shift+D` в актуальних версіях).
4. XMCL автоматично збере системні логи та конфігурацію в єдиний `.zip` архів на вашому робочому столі або у вибраній папці (наприклад, `xmcl-diagnostic-2026-10-26.zip`).

Якщо XMCL взагалі не відкривається, архів можна зібрати вручну з системної папки логів:
- **Windows**: `%APPDATA%\xmcl\logs\`
- **macOS**: `~/Library/Application Support/xmcl/logs/`
- **Linux**: `~/.config/xmcl/logs/`

---

## 2. Що міститься у звіті?

Архів `.zip` є прозорим і не зашифрованим, тому ви можете розпакувати його і переглянути кожен файл перед передачею:

| Файл / Каталог | Вміст і призначення |
| :--- | :--- |
| `main.log` | Журнал головного фонового процесу Electron/DeskGap: запуск, операції введення-виведення файлів, IPC-повідомлення, перевірка оновлень. |
| `renderer.log` | Журнал інтерфейсу користувача: цикл відтворення Vue 3, помилки фронтенду, переходи між вкладками. |
| `device.json` | Технічна інформація про систему: версія ОС, збірка ядра, обсяг оперативної пам'яті (RAM), архітектура CPU (`x64`, `arm64`), модель і виробник GPU. |
| `java.json` | Виявлені у системі середовища Java: версії, шляхи, мажорні номери, постачальник (`Adoptium`, `Oracle`, `Zulu`). |
| `instance.json` (очищений) | Конфігурація активного екземпляра: версія Minecraft, лоадер (Fabric, Forge, NeoForge, Quilt), виділена пам'ять (`-Xmx`), аргументи JVM. |
| `network.log` | Запити завантаження компонентів, дзеркала завантажень, діагностика STUN/TURN рукостискань для P2P кімнат. |

## 3. Сувора приватність: що НІКОЛИ не збирається

XMCL розробляється на основі локального підходу та повної відкритості сирцевого коду. У діагностичний звіт категорично заборонено записувати:

- **Токени авторизації Microsoft / Xbox**: токени сесій (`Access Token`, `Refresh Token`) зберігаються виключно в захищеному сховищі операційної системи (Windows DPAPI, macOS Keychain, Linux Secret Service) і ніколи не потрапляють у логи.
- **Паролі сторонніх / офлайн систем**: жодні паролі, ключі чи секрети серверів не зберігаються у текстовому вигляді.
- **Особисті шляхи та імена користувача**: шляхи, що містять імена ваших локальних облікових записів системи (наприклад, `C:\Users\Ім'я\`), автоматично маскуються як `<USER_HOME>` або замінюються анонімними плейсхолдерами.
- **Світи, збереження та чати**: файли світів, інвентарі гравців, історія внутрішньоігрового чату та список IP-адрес серверів із `servers.dat` повністю виключені зі звіту.

## 4. Перевірка перед відправкою

Перед публікацією діагностичного архіву на форумах:

1. **Розпакуйте та перегляньте**: відкрийте архів будь-яким архіватором (7-Zip, WinRAR тощо).
2. **Перевірте чутливі дані**: за бажанням відкрийте `main.log` або `renderer.log` у текстовому редакторі та скористайтеся пошуком, якщо хочете переконатися у відсутності внутрішніх локальних імен мережі чи специфічних назв папок.
3. **Видаліть непотрібне**: якщо проблема стосується виключно запуску інтерфейсу, ви можете видалити старі логи самої гри з архіву.

Після перевірки ви можете передати звіт розробникам через офіційні канали:

- **GitHub Issues**: прикріпіть файл `.zip` до вашого повідомлення про проблему у репозиторії [voxelum/x-minecraft-launcher/issues](https://github.com/voxelum/x-minecraft-launcher/issues).
- **Офіційний Discord**: надішліть у канал `#support` або `#troubleshooting` на [сервері XMCL Discord](https://discord.gg/W57tNmF).
- **Reddit**: використовуйте сервіс [mclo.gs](https://mclo.gs) для публікації текстових фрагментів та створіть тему у спільноті [r/xmcl](https://www.reddit.com/r/xmcl/).

Ніколи не публікуйте повні логи на неперевірені публічні сервіси для тексту. Для Discord та GitHub завжди використовуйте [mclo.gs](https://mclo.gs), який автоматично приховує випадково виявлені IP-адреси та конфіденційні шляхи.
