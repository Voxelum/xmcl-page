# Журнали збоїв та коди виходу

::: tip ЦЕНТР ДІАГНОСТИКИ ТА ЗБОЇВ
Шукаєте способи виправлення помилок або діагностичний звіт?
- **[Вирішення проблем із запуском та збоями](./troubleshooting.md)** - помилки Java, виділення пам'яті, драйвери та конфлікти модів.
- **[Діагностичний звіт (.zip) та приватність](./diagnostic-report.md)** - як створити повний діагностичний архів XMCL без розкриття особистих даних.
:::

Коли Minecraft аварійно завершує роботу, гра або віртуальна машина Java (JVM) генерують текстові логи з описом точної причини збою. Розуміння цих логів дозволяє вирішити більшість проблем за кілька хвилин.

---

## 1. Де знайти журнали збоїв (Logs)

Усі журнали зберігаються всередині каталогу конкретного екземпляра:

| Тип журналу | Шлях до файлу | Що містить |
| :--- | :--- | :--- |
| **Останній лог сесії** | `<instance>/logs/latest.log` | Повний вивід консолі Minecraft: ініціалізація завантажувача, завантаження модів, підключення до мережі та попередження. |
| **Звіт про збій гри** | `<instance>/crash-reports/crash-<date>-client.txt` | Детальний звіт у разі неперехопленого винятку в Java (Crash report), містить повний стек викликів (stack trace). |
| **Фатальний збій JVM** | `<instance>/hs_err_pid<pid>.log` | Глибокий системний збій на рівні C++/драйверів відеокарти/пам'яті (падіння віртуальної машини Java). |
| **Логи самого XMCL** | Меню XMCL -> Налаштування -> Відкрити папку логів | Робота інтерфейсу лаунчера, завантаження файлів, підключення P2P та системні логи процесу. |

> Швидкий доступ: у вікні екземпляра XMCL натисніть **Відкрити теку** -> відкрийте підпапку `logs` або `crash-reports`.

## 2. Поширені коди виходу Minecraft

Після аварійного закриття XMCL відображає код виходу процесу:

### Код `0` (Нормальний вихід)
- **Причина**: процес завершився штатно. Якщо вікно гри просто зникло, це зазвичай викликано зовнішнім утилітами оптимізації або примусовим закриттям через диспетчер завдань.

### Код `1` (Помилка модуля або модифікацій)
- **Причина**: Загальний код помилки. Найчастіше: конфлікт між модами, відсутність бібліотеки-залежності, синтаксична помилка в конфігураційному файлі (`config/*.json` або `.toml`).
- **Рішення**: Відкрийте `crash-reports/latest.log` і знайдіть перше ключове слово `Caused by:` або `Missing dependencies:`.

### Код `-1` або `255`
- **Причина**: Фатальний виняток під час ініціалізації середовища Minecraft (наприклад, не вдалося завантажити ресурси текстур, збій завантажувача мов або несумісність CoreMod/Mixin).

### Код `0xC0000005` (`-1073741819`) — Порушення доступу до пам'яті (Access Violation)
- **Причина**: Відеодрайвер або стороння програма з оверлеєм (Discord Overlay, RivaTuner, MSI Afterburner, Razer Synapse, GeForce Experience) намагалися несанкціоновано звернутися до пам'яті процесу Java.
- **Рішення**: Вимкніть сторонні оверлеї, перевстановіть драйвери відеокарти за допомогою чистої інсталяції та переконайтеся, що оперативна пам'ять не має збоїв.

### Код `0xC0000409` (`-1073740791`) — Переповнення буфера стека
- **Причина**: Збій драйверів графіки або конфлікт шейдерів Iris/Oculus/OptiFine на нових версіях драйверів.

### Код `137` (SIGKILL / Out of Memory)
- **Причина**: Операційна система (особливо в середовищі Linux або macOS) примусово вбила процес гри через вичерпання фізичної оперативної пам'яті.
- **Рішення**: Збільшіть виділену пам'ять в XMCL або закрийте важкі фонові програми (веб-браузери тощо).

## 3. Як читати Stack Trace (Стек викликів)

Звіт про збій завжди містить блок стеку викликів. Приклад:

```text
java.lang.NullPointerException: Cannot invoke method on null
    at com.example.coolmod.client.Renderer.renderItem(Renderer.java:142)
    at net.minecraft.client.renderer.ItemRenderer.render(ItemRenderer.java:85)
```

1. **Дивіться на перші рядки**: зверніть увагу на назву пакету після `at`.
2. **Визначте винуватця**: у прикладі `com.example.coolmod` вказує на конкретний мод (`coolmod`).
3. **Знайдіть `Caused by:`**: прокрутіть до нижньої частини стектрейсу — там вказана першопричина проблеми.

## 4. Як правильно ділитися журналами

Ніколи не копіюйте величезний текст логу безпосередньо в чат Discord або коментарі GitHub.
- Скористайтеся спеціалізованим сервісом **[mclo.gs](https://mclo.gs)**: просто перетягніть файл `latest.log` або звіт про збій у вікно сайту. Сервіс автоматично приховає ваші системні імена, шляхи та IP-адреси, а також підсвітить помилки.
- Надішліть отримане посилання в службу підтримки або створіть Issue на GitHub.
